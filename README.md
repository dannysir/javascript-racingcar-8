## 🧐  목표 계획서.

### 요구 사항.

**입력**
- 입력은 2회 받는다.
  1. 참가 인원 이름. (`,`쉼표로 구분)
  2. 진행 횟수. (숫자 입력)

**게임 진행**
- 전진하는 조건은 0에서 9 사이에서 무작위 값을 구한 후 무작위 값이 4 이상일 경우만 전진.

**출력**
- 우승자를 출력.
- 우승자는 한명 이상일 수 있음.
- 우승자가 한명 이상일 경우 `,`쉼표로 구분.

**예외 처리**
- 사용자가 잘못된 입력을 입력할 경우 `'[ERROR]'`로 시작하는 메시지 출력 후, `Error`를 던짐.

### 🚨 추가된 프로그래밍 요구 사항.

- indent(인덴트, 들여쓰기) depth를 3이 넘지 않도록 구현한다.
  - 예를 들어 while문 안에 if문이 있으면 들여쓰기는 2이다.
- 3항 연산자 X.
- 함수(또는 메서드)가 한 가지 일만 하도록 최대한 작게.
- Jest를 이용하여 정리한 기능 목록이 정상적으로 작동하는지 테스트 코드로 확인.
  - 테스트 도구 사용법이 익숙하지 않다면 아래 문서를 참고하여 학습한 후 테스트를 구현.


### **학습 키워드.**

- **Jest**
  - 다양한 Matchers 학습.
  - 비동기 함수 테스트.
  - mock 함수 사용법 학습 (기본 제공 `mockQuestions`, `mockRandoms`의 동작 확인).

## 🎯 **체크 리스트.**

### **프로젝트 세팅**

☑️ 포그 & 브랜치 생성.

☑️ 스타일 라이브러리 설정.

### **입력**

☑️ 참가자 이름 입력 받기.

☑️ 진행 횟수 입력 받기.

### **게임 진행**

☑️ 게임 진행시 각각의 플레이어가 0 ~ 9까지 랜덤한 숫자 생성.

☑️ 플레이어가 4 이상의 숫자가 나올 경우 전진.

### **출력**

☑️ 매 진행 상황마다 입력한 이름 순으로 결과 출력.

☑️ 전진은 `-`로 표시.

☑️ 게임 진행을 완료한 후 결과 출력.

☑️ 우승자가 1명 이상일 경우 `,` 쉼표를 기준으로 구분하여 출력.

### **예외 처리**

☑️ 입력 받은 이름은 반드시 `,` 쉼표를 기준으로 구분.

☑️ 입력 받은 이름은 `5`자 이하.

☑️ 진행 횟수는 반드시 숫자.

## 📋 셀프 체크 리스트

☑️ depth는 최대 3인가.

☑️ 3항 연산자는 쓰지 않았는가.

☑️ 함수는 최대한 작게 만들어 한가지 기능만 하도록 했는가.
